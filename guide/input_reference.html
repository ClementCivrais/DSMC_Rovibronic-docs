Input Reference

The present page enumerates the dictionaries and keys specific to the rovibronic extension. Stock OpenFOAM DSMC options are documented in the OpenFOAM user guide and are not repeated here. Every key listed below has been cross-referenced against its parser in src/lagrangian/DSMC/clouds/dsmcCloud.C (or the neighbouring sub-model readers), so that the documentation reflects the keys that the solver actually reads, rather than an idealised interface.

Case directory layout

A canonical rovibronic case follows the standard OpenFOAM three-fold layout (the cases under run/0D/ and tutorials/):

myCase/
├── constant/
│   ├── dsmcProperties         # primary solver configuration
│   ├── speciesCache/          # level-table cache written at start-up
│   └── polyMesh/              # OpenFOAM mesh
└── system/
    ├── controlDict            # time stepping, output frequency
    ├── blockMeshDict          # mesh generator input
    ├── dsmcInitialiseDict     # particle initialisation
    ├── boundariesDict         # boundary conditions
    ├── chemReactDict          # chemical reactions
    ├── controllersDict        # flow controllers (optional)
    ├── fieldPropertiesDict    # field-sampling controls
    ├── decomposeParDict       # parallel decomposition
    └── fvSchemes, fvSolution  # (unused by DSMC but required)

All masses and collision parameters come from the frozen species database (Species database: sources, generation and lock); collisionProperties/Tref must equal the 273 K to which they are referenced, and any other value stops the solver.

Relaxation collision numbers

The three collision numbers \(Z_r\), \(Z_{rv}\), and \(Z_{rve}\) govern the rotational, rovibrational, and rovibronic relaxation rates respectively, and enter the parallel-marginal cascade discussed in Internal-energy relaxation. Representative orders of magnitude, drawn from air chemistry at \(10^4~\mathrm{K}\), are:

  • \(Z_r \sim 2\text{–}10\) — the rotational mode relaxes within a few collisions;

  • \(Z_{rv} \sim 50\text{–}500\) — the vibrational mode is slower by one to two orders of magnitude;

  • \(Z_{rve} \sim 500\text{–}5000\) — the electronic mode is the slowest and is only weakly populated below a few tens of thousands of Kelvin.

Setting any \(Z_k \to \infty\) effectively freezes the corresponding mode and is used as a diagnostic during the phase-by-phase validation protocol (see Validation).

In addition to the three composite collision numbers, collisionProperties accepts an optional fourth, pure-vibrational collision number and a set of keys that switch the constant vibrational collision number for a temperature- and partner-dependent \(Z_v(T)\).

Vibrational-relaxation model

Key

Type

Example

Role

vibrationalRelaxationCollisionNumber

scalar

5

Constant collision number for the pure-vibrational (V-T) window channel. Defaults to a very large value (channel off).

vibrationalRelaxationModel

word

valentini

constant (legacy constant \(Z_v\)), millikanWhite or valentini (temperature-dependent \(Z_v(T)\); valentini additionally consults the per-pair table). If absent, \(Z_v(T)\) is auto-enabled when vibB1 > 0.

vibrationalRelaxationChannel

word

pureVib

rovib (default) routes \(Z_v(T)\) to the rovibrational \((v,J)\) channel; pureVib routes it to the pure-vibrational \(v\)-only channel.

vibrationalSamplingMethod

word

metropolisHastings

Sampler for the joint multi-mode vibrational state of POLYATOMIC molecules (Pfeiffer et al., Phys. Fluids 28, 027103 (2016), Sec. III). acceptanceRejection (default) keeps the joint acceptance-rejection kernel; metropolisHastings switches the nonreactive vib channel and the post-reaction product redistribution to the random-walk Metropolis chain (paper Eqs. 31-32), whose cost grows linearly with the number of modes — recommended for many-mode species such as CH4. Both samplers target the identical distribution (verified to detailed balance); diatomics are unaffected. See docs/Development/Verification/pfeiffer2016_relaxation_conformance.md.

metropolisWalkLength

label

500

Random-walk length \(N_M\) of the Metropolis chain (default 500, the paper’s recommendation; CO2 needs \(\geq 500\), CH4 is insensitive down to 100).

vibB1, vibB2, vibTHT

scalar

30700, 0, 50000

Global generalised-Millikan-White constants \((B_1, B_2)\) and the Park high-temperature limiter temperature \(T_{\mathrm{HT}}\) (default 30000 K). See Internal-energy relaxation.

vibrationalRelaxationData

dict

see below

Per-pair \((B_1, B_2, T_{\mathrm{HT}})\) overrides, nested by vibrating species then collision partner.

The per-pair table is keyed by the vibrating species and then by the collision partner (both must be members of typeIdList); a per-relaxer default block sets all partners of a vibrator, and explicit partner blocks override individual pairs:

collisionProperties
{
    Tref                                    273;
    vibrationalRelaxationModel              valentini;  // partner-dependent
    vibrationalRelaxationChannel            pureVib;    // Z_v(T) -> v-only
    vibrationalRelaxationCollisionNumber    1e30;       // overridden by Z_v(T)
    vibTHT                                  50000;

    vibrationalRelaxationData
    {
        N2
        {
            N2 { B1 30700; B2 0; THT 50000; }   // N2-N2 slow
            O  { B1 6140;  B2 0; THT 50000; }   // N2-O  fast
            Ar { B1 30700; B2 0; THT 50000; }   // N2-Ar slow
        }
    }
}

Diagnostics: per-channel transition counters

countInternalTransitions (Switch, collisionProperties, default off) enables cumulative per-species transition-event counters for the four LB window channels — rotational \(J \to J'\), pure-vibrational \(v \to v'\), rovibrational \(v \to v'\) (aggregated over the final \(J'\)), and rovibronic \(n \to n'\) — incremented at every non-reaction LB draw and printed to the log (tag itc) together with per-species state-population snapshots at every write time. Combined with the reservoir normalisation

\[k_{s \to s'} = \frac{\Delta(\text{counts})}{\Delta t \; N_{s} \; n_{\mathrm{tot}}}\]

this measures state-to-state rate coefficients directly (see docs/Development/Verification/lb_state_to_state_rates.md). Enable only in non-reactive runs: reaction-class trial redistributions pass through the same sampler and would pollute the tallies.

Per-species model switches (moleculeProperties)

The optional moleculeProperties sub-dictionary, keyed by species name, accepts only model switches:

  • allowSpinForbiddenTransitions (bool) — flips the electronic spin-conservation gate per species: true connects the full electronic manifold, false restricts LB electronic relaxation (and equilibrium initialisation) to the initial state’s spin-multiplicity class;

  • vibrationalCoupling (word) — separable or coupled polyatomic vibration (Rovibronic level structure).

moleculeProperties
{
    O2 { allowSpinForbiddenTransitions false; }   // spin-blocked
}

The species data are frozen. An entry that sets mass, diameter, omega, alpha, charge, rotationalDegreesOfFreedom, vibrationalModes, maintainOddEvenParity, internalEnergyList, degeneracyList or dissociationEnergy stops the solver with a FatalError (see Species database: sources, generation and lock).

rovibronicDatabase sub-dictionary

Required; a case without it stops at start-up.

  • computeEnergyLevels (Switch, default true) — builds the \((n, v, J)\) energy and degeneracy tables at start-up from the compiled species database. With false the diatomic and atomic tables are read back from databasePath when a cache file exists.

  • databasePath (fileName, optional) — directory in which the tables are cached, conventionally "constant/speciesCache".

constant/speciesCache/

The species data are compiled into the solver, not read from the case. When databasePath is set, the solver writes one <species>.dat file per diatomic or atomic species (level table, degeneracies, dissociation and ionisation energies, spin multiplicities) as a cache; polyatomic ladders are not cached. The cache is not validated against the database: after a database change, rename every cache that may be read (the solver with computeEnergyLevels false, or a Python oracle) and regenerate it with dsmcInitialise. The origin of every constant is documented in Species database: sources, generation and lock.

system/dsmcInitialiseDict

Specifies the initial particle distribution. The main entries are:

  • configurations (list) — one entry per sub-domain to populate. Each entry contains:

    • type — fill strategy (dsmcMeshFill is the standard whole-domain option; velocities are drawn from a Maxwellian);

    • numberDensities — per-species number density in \(\mathrm{m}^{-3}\);

    • translationalTemperature — Maxwell-Boltzmann sampling temperature for the particle velocities;

    • internalTemperature — Boltzmann sampling temperature used for the rovibronic state indices \((n, v, J)\) (a single internal temperature; separate rotational, vibrational or electronic temperatures are not read);

    • velocity — bulk flow velocity (vector).

Example:

configurations
(
    configuration
    {
        type                        dsmcMeshFill;
        numberDensities
        {
            O2      1e23;
        };
        translationalTemperature    20000;
        internalTemperature         20000;
        velocity                    (0 0 0);
    }
);

system/boundariesDict

Three top-level lists are read: dsmcPatchBoundaries, dsmcCyclicBoundaries, and dsmcGeneralBoundaries. Each entry pairs a patch name with a boundaryModel drawn from the classes listed below.

system/chemReactDict

Every reaction is an entry of the reactions list; an empty list runs the case without chemistry. Each entry names a reactionModel and carries a dsmcReactionProperties sub-dictionary:

reactions
(
    oxygenDissociation
    {
        reactionModel   dissociationIonisationTypeISameSpecies;

        dsmcReactionProperties
        {
            reaction                      oxygenDissociation;
            reactants                     (O2 O2);
            productsOfDissociatedMolecule (O O);
            productsOfIonisedMolecule     (O2+ E-);
            allowSplitting                yes;
            writeRatesToTerminal          no;
        }
    }
);

The dissociation, exchange and ionisation thresholds of the QK classes are computed automatically from the database entries (\(D_0 = E_{\mathrm{diss}}(n{=}0, v{=}0, J{=}0)\) and the ionisation potentials) and are not supplied by the user.

A detailed description of each reaction model is given in Neutral chemistry.

HCAO local-mode reaction models

The channel-specific reaction models of Lauterbach, Tuttas & Pfeiffer (2026) are compiled, but they act only on local-mode polyatomic species (database vibModeBasis localMode), and the frozen species database on the main branch carries no such species; a reaction that names a normal-mode species stops with a FatalError. Their keys are:

  • polyDissociationQKHCAO — one dissociation channel per local stretching mode (paper Eqs. 19–22). Keys: reactants (A M), a channels sub-dictionary with one named block per breaking bond carrying stretchMode (0-based mode index), productMolecule, productAtom and formationEnergy (\(-D_{0,j}\) [J]); optional rotationCouplingGamma (paper Eq. 36, default 0). Competing open channels are drawn weighted by their excess energy.

  • polyExchangeQK — mode-coupled QK exchange (paper Eqs. 23–26). Keys: productsOfExchangeReaction (C D), activationEnergy (the energetic barrier \(E_a\) [J], not an Arrhenius fit), modeCouplingAlpha (per-mode \(\alpha_j\) list, one entry broadcasts), optional stericFactor (\(\sigma\), default 1), formationEnergy (0 K reaction energy for the post-reaction ledger), optional rotationCouplingGamma (Eq. 37, default 0).

Gas-surface interaction dictionaries

The models are described in Wall and inflow models and verified in Gas-surface interaction verification. The keywords below are those read by the source; the class headers under src/lagrangian/DSMC/ carry the same Usage blocks.

Wall temperature (every re-emitting wall)

Read from <boundaryModel>Properties by every wall that re-emits at a wall temperature (diffuse, mixed, CLL, accommodation, pump, outgassing, catalytic, ablating and coverage walls):

temperature            1000;   // uniform value, initial face value
wallTemperatureModel   radiativeEquilibrium;  // uniform (default) |
                                              // radiativeEquilibrium |
                                              // coupled
wallTemperatureProperties      // radiativeEquilibrium only
{
    emissivity            0.85;   // (0, 1], required
    backgroundTemperature 0;      // radiative sink [K]
    relaxationFactor      0.2;    // (0, 1]
    updateInterval        10;     // steps per update
    minTemperature        50;
    maxTemperature        1e5;
    sampleStartTime       0;      // start of the Tw/q averaging ledger
}

A non-uniform model on a wall that does not re-emit at a face temperature (specular, deletion, the *Field* walls, the dedicated radiative-equilibrium wall) is a FatalError; coupled is set by the conjugate solid of dsmcFoamAblation.

The conjugate solid, in constant/conjugateProperties (it recedes the wall itself, so it excludes ablationRecession):

emissivity            0.85;
backgroundTemperature 0;

prescribedHeatFlux    1e7;    // optional (verification)

meltFilm                      // optional
{
    bodyForce         (0 0 0);
    freeFlight        no;
    separation        full;   // full | partial | none
    weberCritical     12;
    maxCourant        0.4;
    sampleInterval    5;
    dropletEmissivity 0.1;
    // prescribedShear, initialFilm { }, testDroplet { } (verification)
}

Each solid region has constant/<region>/polyMesh, dynamicMeshDict (a motion solver, to recede) and solidProperties (rho, cp, k, Tmelt, Lmelt, T0; cp and k may be any Function1 of \(T\); optional cellZones overrides; for the film rhoLiquid, muLiquid, sigmaLiquid, cpLiquid and optionally Tboil, Lvap, molarMass), system/<region>/fvSchemes and fvSolution, 0/<region>/T (mixed on the coupled patches) and 0/<region>/pointDisplacement (fixedValue on the coupled patches). constant/regionProperties (regions ( gas (region0) solid (solid) );) is read by decomposePar -allRegions and reconstructPar -allRegions. The couplings must be disjoint: no patch in two couplings and no point shared by two coupled patches of one mesh. The former solidCase layout is refused.
