Input Reference

The present page enumerates the dictionaries and keys specific to the rovibronic extension. Stock OpenFOAM DSMC options are documented in the OpenFOAM user guide and are not repeated here. Every key listed below has been cross-referenced against its parser in src/lagrangian/DSMC/clouds/dsmcCloud.C (or the neighbouring sub-model readers), so that the documentation reflects the keys that the solver actually reads, rather than an idealised interface.

Case directory layout

A canonical rovibronic case follows the standard OpenFOAM three-fold layout. The reference tutorial run/Tutorial/ is organised as:

Tutorial/
├── constant/
│   ├── dsmcProperties         # primary solver configuration
│   ├── speciesCache/          # species database (one .dat per species)
│   └── polyMesh/              # OpenFOAM mesh
└── system/
    ├── controlDict            # time stepping, output frequency
    ├── blockMeshDict          # mesh generator input
    ├── dsmcInitialiseDict     # particle initialisation
    ├── boundariesDict         # boundary conditions
    ├── chemReactDict          # chemical reactions
    ├── controllersDict        # flow controllers (optional)
    ├── fieldPropertiesDict    # field-sampling controls
    ├── decomposeParDict       # parallel decomposition
    └── fvSchemes, fvSolution  # (unused by DSMC but required)

Relaxation collision numbers

The three collision numbers \(Z_r\), \(Z_{rv}\), and \(Z_{rve}\) govern the rotational, rovibrational, and rovibronic relaxation rates respectively, and enter the parallel-marginal cascade discussed in Internal-energy relaxation. Representative orders of magnitude, drawn from air chemistry at \(10^4~\mathrm{K}\), are:

  • \(Z_r \sim 2\text{–}10\) — the rotational mode relaxes within a few collisions;

  • \(Z_{rv} \sim 50\text{–}500\) — the vibrational mode is slower by one to two orders of magnitude;

  • \(Z_{rve} \sim 500\text{–}5000\) — the electronic mode is the slowest and is only weakly populated below a few tens of thousands of Kelvin.

Setting any \(Z_k \to \infty\) effectively freezes the corresponding mode and is used as a diagnostic during the phase-by-phase validation protocol (see Validation).

In addition to the three composite collision numbers, the collision-model coefficients sub-dictionary (named <Model>Coeffs or, in the relaxation cases, collisionProperties) accepts an optional fourth, pure-vibrational collision number and a set of keys that switch the constant vibrational collision number for a temperature- and partner-dependent \(Z_v(T)\).

Vibrational-relaxation model

Key

Type

Example

Role

vibrationalRelaxationCollisionNumber

scalar

5

Constant collision number for the pure-vibrational (V-T) window channel. Defaults to a very large value (channel off).

vibrationalRelaxationModel

word

valentini

constant (legacy constant \(Z_v\)), millikanWhite or valentini (temperature-dependent \(Z_v(T)\); valentini additionally consults the per-pair table). If absent, \(Z_v(T)\) is auto-enabled when vibB1 > 0.

vibrationalRelaxationChannel

word

pureVib

rovib (default) routes \(Z_v(T)\) to the rovibrational \((v,J)\) channel; pureVib routes it to the pure-vibrational \(v\)-only channel.

vibrationalSamplingMethod

word

metropolisHastings

Sampler for the joint multi-mode vibrational state of POLYATOMIC molecules (Pfeiffer et al., Phys. Fluids 28, 027103 (2016), Sec. III). acceptanceRejection (default) keeps the joint acceptance-rejection kernel; metropolisHastings switches the nonreactive vib channel and the post-reaction product redistribution to the random-walk Metropolis chain (paper Eqs. 31-32), whose cost grows linearly with the number of modes — recommended for many-mode species such as CH4. Both samplers target the identical distribution (verified to detailed balance); diatomics are unaffected. See docs/verification/pfeiffer2016_relaxation_conformance.md.

metropolisWalkLength

label

500

Random-walk length \(N_M\) of the Metropolis chain (default 500, the paper’s recommendation; CO2 needs \(\geq 500\), CH4 is insensitive down to 100).

vibB1, vibB2, vibTHT

scalar

30700, 0, 50000

Global generalised-Millikan-White constants \((B_1, B_2)\) and the Park high-temperature limiter temperature \(T_{\mathrm{HT}}\) (default 30000 K). See Internal-energy relaxation.

vibrationalRelaxationData

dict

see below

Per-pair \((B_1, B_2, T_{\mathrm{HT}})\) overrides, nested by vibrating species then collision partner.

The per-pair table is keyed by the vibrating species and then by the collision partner (both must be members of typeIdList); a per-relaxer default block sets all partners of a vibrator, and explicit partner blocks override individual pairs:

collisionProperties
{
    Tref                                    1000;
    vibrationalRelaxationModel              valentini;  // partner-dependent
    vibrationalRelaxationChannel            pureVib;    // Z_v(T) -> v-only
    vibrationalRelaxationCollisionNumber    1e30;       // overridden by Z_v(T)
    vibTHT                                  50000;

    vibrationalRelaxationData
    {
        N2
        {
            N2 { B1 30700; B2 0; THT 50000; }   // N2-N2 slow
            O  { B1 6140;  B2 0; THT 50000; }   // N2-O  fast
            Ar { B1 30700; B2 0; THT 50000; }   // N2-Ar slow
        }
    }
}

rovibronicDatabase sub-dictionary

  • computeEnergyLevels (Switch) — if true, the solver builds the \((n, v, J)\) energy and degeneracy tables at start-up from the species database.

  • databasePath (fileName) — directory containing the per-species .dat files. In the reference tutorial this points to constant/speciesCache.

constant/speciesCache/

The species database is distributed as one ASCII .dat file per species, named after the species symbol (e.g. O2.dat, N2.dat, NO.dat). The reference tutorial ships 259 such files, covering the diatomic molecules of air chemistry, their atomic fragments, the first few ion species, and the electron.

Each file contains, in order:

  1. the Variable Soft Sphere (VSS) collision parameters (\(\sigma_{\mathrm{ref}}\), \(\omega\), \(\alpha\), \(T_{\mathrm{ref}}\));

  2. the Dunham coefficients fitted to an ab-initio potential energy surface, one block per electronic state;

  3. the three-dimensional internalEnergyList[n][v][J] table, in Joules, with the \((0, 0, 0)\) ground-state level normalised to zero;

  4. the associated degeneracy table degeneracyList[n][v][J], which accounts for the rotational multiplicity \((2J+1)\) and the electronic degeneracy \(g_{\mathrm{elec}}^{(n)}\);

  5. the ionisation potential and, for molecules, the dissociation energy.

Provenance and fit quality of the Dunham coefficients are documented in docs/Database/dunham_coefficients_from_ab_initio_PES.md.

system/dsmcInitialiseDict

Specifies the initial particle distribution. The main entries are:

  • configurations (list) — one entry per sub-domain to populate. Each entry contains:

    • type — fill strategy (dsmcMeshFill is the standard whole-domain option);

    • initialDistributionType — velocity distribution; typically maxwellian;

    • numberDensities — per-species number density in \(\mathrm{m}^{-3}\);

    • translationalTemperature — Maxwell-Boltzmann sampling temperature for the particle velocities;

    • internalTemperature — Boltzmann sampling temperature used for the rovibronic state indices \((n, v, J)\);

    • rotationalTemperature / vibrationalTemperature (optional, dsmcMeshFill only) — SPLIT internal temperatures for two-temperature reservoir setups (\(T_R \neq T_V\)); both default to internalTemperature. Currently implemented for polyatomic species (rotation + electronic sampled at \(T_R\), the joint vibrational state at \(T_V\)); requesting a split for a diatomic is a fatal error. Used by the Pfeiffer et al. 2016 verification reservoirs (run/0D/pfeiffer2016_verification);

    • velocity — bulk flow velocity (vector).

Example:

configurations
(
    configuration
    {
        type                        dsmcMeshFill;
        initialDistributionType     maxwellian;
        numberDensities
        {
            O2      1e23;
        };
        translationalTemperature    20000;
        internalTemperature         20000;
        velocity                    (0 0 0);
    }
);

Three top-level lists are read: dsmcPatchBoundaries, dsmcCyclicBoundaries, and dsmcGeneralBoundaries. Each entry pairs a patch name with a boundaryModel drawn from the classes listed below.

system/chemReactDict

Enabled when chemicalReactions is set to true in dsmcProperties. Each reaction is specified as a named block of the form:

reactionName
{
    reactionModel      dissociationIonisationTypeISameSpecies;
    reactants          (N2 N2);
    productsOfDissociationReaction (N N N2);
    aCoeff             ...;
    bCoeff             ...;
}

The dissociation and atom-exchange heats of reaction are computed automatically from the database entries \(D_0 = E_{\mathrm{diss}}(n{=}0, v{=}0, J{=}0)\) and do not need to be supplied by the user. Only the ionisation heat, which depends on an input ionisation potential, remains a user-facing parameter.

A detailed description of each reaction model is given in Neutral chemistry.

For local-mode (HCAO) polyatomic species — database entries with vibModeBasis localMode, e.g. H2O_HCAO, HCN_HCAO, CH4_HCAO, CH3_HCAO — the channel-specific reaction models of Lauterbach, Tuttas & Pfeiffer (2026) are available:

  • polyDissociationQKHCAO — one dissociation channel per local stretching mode (paper Eqs. 19–22). Keys: reactants (A M), a channels sub-dictionary with one named block per breaking bond carrying stretchMode (0-based mode index), productMolecule, productAtom and formationEnergy (\(-D_{0,j}\) [J]); optional rotationCouplingGamma (paper Eq. 36, default 0). Competing open channels are drawn weighted by their excess energy.

  • polyExchangeQK — mode-coupled QK exchange (paper Eqs. 23–26). Keys: productsOfExchangeReaction (C D), activationEnergy (the energetic barrier \(E_a\) [J], not an Arrhenius fit), modeCouplingAlpha (per-mode \(\alpha_j\) list, one entry broadcasts), optional stericFactor (\(\sigma\), default 1), formationEnergy (0 K reaction energy for the post-reaction ledger), optional rotationCouplingGamma (Eq. 37, default 0).

  • polyRecombinationQK / polyRecombinationTCE — optional thirdBodies (M1 M2 ...) replaces the single thirdBody when the paper’s “M = any species” equilibrium cases are run; the QK class additionally accepts manifoldSum binned (exact density-of-states convolution, needed for large-manifold species such as CH4; default exact).

Example cases: run/0D/HCAO_validation.

Gas-surface interaction dictionaries

The reactive walls (dsmcCatalyticWallPatch, dsmcAblatingWallPatch, dsmcCoverageWallPatch) read their surface reactions either inline or by name against a central system/surfaceChemReactDict, which carries surfaceReactions and surfaceMaterials blocks. A finite-rate reaction has the generalised-Arrhenius probability \(\beta = \min(1, A\,T_w^{n}\,e^{-T_a/T_w})\); a recombination reaction has a constant, Arrhenius or tabulated \(\gamma\):

surfaceReactions
{
    oxidiseO   { type srFiniteRate; reactant O;  product CO;
                 A 0.63; n 0.0; Ta 1160.0;
                 nCConsumed 1; nReactantConsumed 1; }
    boudouard  { type srFiniteRate; reactant CO2; product CO;
                 secondaryProduct CO; A 0.9; n 0.0; Ta 0.0;
                 nCConsumed 1; nReactantConsumed 1; }
    recombineO { type srRecombination; reactant O; product O2;
                 gamma 0.07; }
}
surfaceMaterials
{
    graphite { solidDensity 1800; carbonMass 1.994e-26;
               siteDensity 1e19; }
}

The boundary patch then references these reactions by name:

boundaryModel dsmcAblatingWallPatch;
dsmcAblatingWallPatchProperties
{
    temperature 2000;
    velocity    (0 0 0);
    material    graphite;
    reactions   ( oxidiseO oxidiseO2 boudouard recombineO );
}

Geometric surface recession (the immersed level-set of Wall and inflow models) is enabled by an immersedAblationProperties sub-dictionary in constant/dsmcProperties. Its principal keys are the surface specification (shape plane/sphere/cylinder with point / normal or centre / radius, or stlFile for an arbitrary triangulated geometry), the reaction (gamma / A / n / Ta, reactant, product), the solid properties (material or solidDensity + carbonMass), and optional radiativeEquilibrium + emissivity, sublimation + sublimationProducts, and patoCoupling switches:

immersedAblationProperties
{
    stlFile        "constant/triSurface/capsule.stl";
    temperature    1000;
    gamma          1.0;
    solidDensity   50;
    reactant       O;
    product        O2;
    maxPenetration 7e-4;
    perCellRecession true;
}

system/controlDict

Standard OpenFOAM; the rovibronic extension adds a single convenience key:

  • nTerminalOutputs (label) — number of solver time-steps between terminal progress messages.

The application entry is informational only; the executable that must actually be invoked is dsmcFoam, regardless of the string supplied here (the reference tutorial uses dsmcFoamPlus as the colloquial project name).
