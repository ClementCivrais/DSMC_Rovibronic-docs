Species database: sources, generation and lock
==============================================

Source: ``src/lagrangian/DSMC/speciesDatabase/`` and its
``sources/`` sub-directory (``sources/README.md``,
``sources/nist/BUILD_REPORT.md``).

Principle
---------

The species database is **frozen**. Every mass, collision
parameter and spectroscopic constant is generated by a script from
source files stored in the repository, compiled into
``libDSMC_MNF``, and cannot be changed from a case. A change to the
database requires the explicit approval of the code owner, is made
in the sources and the generators, and is committed through a
locked pre-commit hook (see `Repository lock`_). Python oracles and
analysis scripts read the same generated tables, so that the solver
and its verification scripts always use identical numbers.

Files
-----

.. list-table::
   :header-rows: 1
   :widths: 38 62

   * - File
     - Content
   * - ``dsmcSpeciesDatabaseTransport.C``
     - **Generated** by ``sources/build_transport_data.py``:
       species name to chemical formula, masses, per-species VSS
       values and the 378 neutral-neutral pair rows
       (``populateTransport()``).
   * - ``dsmcSpeciesDatabaseSpectroscopy.C``
     - **Generated** by ``sources/build_spectroscopy_data.py``:
       electronic states, Dunham constants, atomic levels,
       dissociation and ionisation energies, nuclear-spin and
       symmetry factors, polyatomic modes and rotational constants
       (``populateSpectroscopy()``).
   * - ``dsmcSpeciesDatabaseFormationEnthalpy.H``
     - **Generated** by the same script: 0 K formation enthalpies
       (ATcT 1.130) on the energy zero of the ladders, read by the
       polyatomic QK classes through ``polyFormationEnergy.H``.
   * - ``dsmcSpeciesDatabaseData.C``
     - Hand-written, **structural and model fields only**: charge,
       ``isAtom``, rotational and vibrational degrees of freedom,
       ``rotationType``, ``vibrationalCoupling``, mode basis and
       dissociation products, SOMO descriptors, bond-order slopes,
       van der Waals wells, polarisabilities and
       ``allowSpinForbiddenTransitions``. It sets no generated field;
       ``sources/strip_generated_fields.py --check`` verifies this.
   * - ``dsmcSpeciesDatabaseCompute.C``
     - Builds the :math:`(n, v, J)` ladders, degeneracies and
       thresholds from the fields above
       (:doc:`../theory/rovibronic_levels`).

The constructor runs ``populateDefaults()``, then
``populateSpectroscopy()``, then ``populateTransport()``, and finally
copies the mass, :math:`d_{\mathrm{ref}}`, :math:`\omega` and
:math:`\alpha` of every species from the frozen tables. A species
that is missing from the frozen tables stops the solver with a
``FatalError``.

The ``sources/`` directory holds the inputs and the tools:

* ``Gosma2025_FULL_VSS_DATABASE.vss`` —  the collision-specific VSS
  set of Gosma et al. (2025), verbatim from the Figshare record
  (doi:10.60893/figshare.pof.28632665), with its SHA-256 checksum;
* ``Pfeiffer2022_TableI.csv`` —  Table I of Pfeiffer (2022);
* ``CIAAW_atomic_weights.csv`` —  conventional atomic weights;
* ``nist/raw/`` —  the NIST WebBook, ASD and CCCBDB pages and the
  ATcT 1.130 table actually used, with ``SHA256SUMS``;
  ``nist/tables/`` holds the hand-maintained assignment tables
  (state selection, asymptote correlations), which carry no
  numbers;
* ``species_properties_frozen.json`` and
  ``species_spectroscopy_frozen.json`` —  the generated Python view
  of every value, with its source and flags;
* ``species_frozen.py`` —  the only interface through which Python
  scripts obtain masses and collision data;
* ``pre-commit-species-lock.sh`` —  the repository lock.

Masses and collision data
-------------------------

The rules below are applied by ``build_transport_data.py``; all
values are referenced to :math:`T_{\mathrm{ref}} = 273~\mathrm{K}`.

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - Data
     - Source
   * - Neutral species, neutral-neutral pairs
     - Gosma, Swaminathan Gopalan, Subramaniam and Stephani (2025),
       *Phys. Fluids* **37**, 036156, collision-specific set fitted
       over 1000–20000 K. A species' own values are its like-pair
       row X-X; a neutral pair X-Y uses Gosma's own X-Y row.
   * - Ions and the electron
     - Pfeiffer (2022), *Phys. Fluids* **34**, 117110, Table I.
   * - H\ :sup:`+`, H\ :sub:`2`\ :sup:`+`, He\ :sup:`+`
     - Gosma like-pair rows (not in Pfeiffer).
   * - CH\ :sup:`+`, NH\ :sup:`+`
     - Neutral parent CH, NH (in no source; proxy).
   * - Any pair with a charged partner
     - Arithmetic mean of :math:`d_{\mathrm{ref}}`, :math:`\omega`,
       :math:`\alpha` (Pfeiffer's collision-averaged convention).
   * - Masses
     - Sum of the CIAAW conventional atomic weights times the
       atomic mass constant (CODATA 2018); an ion carries the mass
       of its neutral.

Bird (1994), Appendix A, is kept as the last resort for a species
that none of these sources reports; no current species needs it.
Species variants (``O2NIST``, ``O2VHS``, ``CO2harm``,
``CH4coupled``, …) map to the formula of their parent and share its
mass and collision data. Representative pair values, as printed by

**Use in the solver.** At start-up ``dsmcCloud`` builds three
:math:`N_s \times N_s` tables, ``dPQ_``, ``omegaPQ_`` and
``alphaPQ_``, once, from ``dsmcSpeciesDatabase::collisionPair()``,
and prints them under
``Collision pairs (d_ref [m], omega, alpha; Tref = 273 K)``. Every
collision model, reaction class, recombination collision rate and
mean-free-path estimate reads the pair value through
``cloud.dPQ(P, Q)``, ``cloud.omegaPQ(P, Q)`` and
``cloud.alphaPQ(P, Q)``; no class forms
:math:`\tfrac{1}{2}(\omega_P + \omega_Q)` itself. The solver stops
if ``collisionProperties/Tref`` differs from the 273 K of the
tables.

**Use in Python.** Oracles and analysis scripts import
``species_frozen``:

.. code-block:: python

   import sys
   sys.path.insert(0, "<repo>/src/lagrangian/DSMC/speciesDatabase/sources")
   import species_frozen as sf
   sf.mass("O2NIST")       # [kg]
   sf.vss("O")             # (d_ref [m], omega, alpha, Tref [K])
   sf.pair("O2NIST", "O")  # the pair values the solver uses
   sf.TREF                 # 273.0

Spectroscopy
------------

``build_spectroscopy_data.py`` parses the stored pages and writes
one row per state, level or mode, each with its source. The rules
are:

* **Diatomic states.** Only states tabulated in the NIST WebBook
  (Huber and Herzberg constants) are carried. Constants that the
  WebBook does not print are set to zero, except where zero is not
  admissible (an unprinted :math:`B_e` or :math:`r_e`); those few
  values, and all constants of CO\ :sup:`+`, CH\ :sup:`+` and
  NH\ :sup:`+`, are kept from earlier sources and flagged
  **NON-NIST** in ``BUILD_REPORT.md``. States that the WebBook does
  not list were removed.
* **Atomic levels.** Each level is the :math:`g`-weighted mean of
  its NIST ASD :math:`J` components,
  :math:`g = \sum_J (2J+1)`, the ground term included. The O and N
  Rydberg groups use ASD energies with the complete-shell
  degeneracy :math:`2n^{2} g_{\mathrm{core}}`, which keeps
  :math:`Q_{\mathrm{el}}` within 2 %.
* **Energy zero.** The zero of an atom or atomic ion is its
  :math:`J`-weighted ground term; the zero of a molecule is
  :math:`v = 0`, :math:`J = 0` of its :math:`T_e = 0` state. ATcT
  refers to the lowest :math:`J` levels, so every dissociation
  limit is shifted to these zeros. For example, :math:`E_d` of the
  O\ :sub:`2` ground state rises by :math:`155.95~\mathrm{cm^{-1}}`,
  twice the :math:`J`-weighted O(:sup:`3`\ P) term, and the
  dissociation products carry exactly the energy removed from the
  molecule.
* **Thermochemistry.** Dissociation energies are
  :math:`D_0` from the ATcT 1.130 0 K formation enthalpies.
  Atomic ionisation energies come from the ASD series limits on
  the :math:`J`-weighted zeros; molecular ionisation energies come
  from ATcT, so that
  :math:`D_0(\mathrm{AB}) + \mathrm{IE}(\mathrm{A})
  = \mathrm{IE}(\mathrm{AB}) + D_0(\mathrm{AB}^{+})` closes within
  one data set.
* **Nuclear spin and symmetry.** The product-rule nuclear-spin
  degeneracy :math:`g_{\mathrm{nuc}} = \prod (2I+1)` is stored for
  every species but applied in no ladder, since it cancels in every
  equilibrium constant. The symmetry number enters every rotor
  branch as :math:`1/\sigma`; homonuclear diatomics carry even/odd
  :math:`J` weights normalised to a :math:`J`-average of
  :math:`1/\sigma`. Before the rebuild the linear and spherical-top
  branches omitted :math:`1/\sigma`, so :math:`Q_{\mathrm{rot}}` of
  CO\ :sub:`2` and C\ :sub:`3` was twice too large and that of
  CH\ :sub:`4` twelve times.
* **Polyatomic species.** CCCBDB supplies the fundamentals,
  rotational constants, bond lengths, point groups and symmetry
  numbers. CCCBDB tabulates no anharmonic constants, so
  N\ :sub:`2`\ O, HCN, C\ :sub:`3`, CH\ :sub:`3`, NH\ :sub:`3`,
  O\ :sub:`3`, NO\ :sub:`2` and CH\ :sub:`2` have harmonic
  ladders; the anharmonic sets of CO\ :sub:`2`, CH\ :sub:`4` and
  H\ :sub:`2`\ O are kept and flagged NON-NIST.

The resulting ladders, as printed by ``dsmcInitialise``, are for
example: O\ :sub:`2`, 7 electronic states and 17389
:math:`(n, v, J)` levels; N\ :sub:`2`, 9 and 45184; NO, 7 and 15971;
CO, 8 and 45521.

Case-level lock
---------------

Species data cannot be changed from a case:

* a ``moleculeProperties/<species>`` entry that sets ``mass``,
  ``diameter``, ``omega``, ``alpha``, ``charge``,
  ``rotationalDegreesOfFreedom``, ``vibrationalModes``,
  ``maintainOddEvenParity``, ``internalEnergyList``,
  ``degeneracyList`` or ``dissociationEnergy`` stops the solver
  with a ``FatalError``;
* a ``dsmcProperties`` without the ``rovibronicDatabase``
  sub-dictionary stops the solver: the former path that read all
  species data from ``moleculeProperties`` no longer exists;
* ``collisionProperties/Tref`` must be 273.

Only model switches remain per species:
``allowSpinForbiddenTransitions`` (electronic spin-conservation
gate) and ``vibrationalCoupling`` (``separable`` or ``coupled``
polyatomic vibration). See :doc:`../guide/input_reference`.

Repository lock
---------------

``sources/pre-commit-species-lock.sh`` is installed as the
repository's pre-commit hook:

.. code-block:: bash

   ln -sf ../../src/lagrangian/DSMC/speciesDatabase/sources/pre-commit-species-lock.sh \
          .git/hooks/pre-commit

It refuses any commit that touches ``speciesDatabase/`` unless
``DSMC_SPECIES_DB_UNLOCK=1`` is set for that one commit, which is
done only with the code owner's approval. In every such commit it
runs ``build_transport_data.py --check``,
``build_spectroscopy_data.py --check`` and
``strip_generated_fields.py --check``: the generated files must
regenerate identically from the stored sources, and
``dsmcSpeciesDatabaseData.C`` must set no generated field.

Changing or adding a species
----------------------------

With the owner's approval:

#. store the new source pages under ``sources/nist/raw/`` (and add
   their checksums to ``SHA256SUMS``), or the new collision data
   next to the Gosma and Pfeiffer files;
#. extend the assignment tables in ``sources/nist/tables/`` and the
   species-to-formula map of ``build_transport_data.py``;
#. add the structural fields to ``dsmcSpeciesDatabaseData.C``;
#. run both generators, then their ``--check`` modes;
#. rebuild ``libDSMC_MNF`` and the solvers;
#. rename every ``constant/speciesCache`` that will be reused
   (for example to ``speciesCache.stale_<date>``): a cache is not
   validated against the database and would silently keep the old
   ladders if it were read;
#. commit with ``DSMC_SPECIES_DB_UNLOCK=1``.

History
-------

Until 2026-09-29 the neutral entries were labelled "Gosma et al.
(2025) Table VI" but held Gosma's *electron-cation* rows (for
instance O\ :sub:`2` = e-O\ :sub:`2`\ :sup:`+`,
:math:`d_{\mathrm{ref}} = 1.502~\text{Å}`, :math:`\omega = 0.501`).
The O\ :sub:`2`-O\ :sub:`2` cross section was therefore 6.6 times
too small at 273 K, and the Larsen-Borgnakke exponent
:math:`3/2 - \omega` was 1.00 instead of 0.80. With the corrected
collision data the QK dissociation rate coefficients rose by a
factor of 1.8–3, while the ground-to-ground exchange rate
:math:`k_{00}` of ``dissociationIonisationExchange`` does not depend
on the collision data
(``run/0D/rates_frozen_transport_20260929/REPORT.md``). Collision
data and rate coefficients quoted in validation records older than
that date refer to the former entries.
