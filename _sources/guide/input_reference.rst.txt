Input Reference
===============

The present page enumerates the dictionaries and keys specific to
the rovibronic extension. Stock OpenFOAM DSMC options are documented
in the OpenFOAM user guide and are not repeated here. Every key
listed below has been cross-referenced against its parser in
``src/lagrangian/DSMC/clouds/dsmcCloud.C`` (or the neighbouring
sub-model readers), so that the documentation reflects the keys
that the solver *actually* reads, rather than an idealised
interface.

Case directory layout
---------------------

A canonical rovibronic case follows the standard OpenFOAM
three-fold layout (the cases under ``run/0D/`` and ``tutorials/``):

.. code-block:: text

   myCase/
   ├── constant/
   │   ├── dsmcProperties         # primary solver configuration
   │   ├── speciesCache/          # level-table cache written at start-up
   │   └── polyMesh/              # OpenFOAM mesh
   └── system/
       ├── controlDict            # time stepping, output frequency
       ├── blockMeshDict          # mesh generator input
       ├── dsmcInitialiseDict     # particle initialisation
       ├── boundariesDict         # boundary conditions
       ├── chemReactDict          # chemical reactions
       ├── controllersDict        # flow controllers (optional)
       ├── fieldPropertiesDict    # field-sampling controls
       ├── decomposeParDict       # parallel decomposition
       └── fvSchemes, fvSolution  # (unused by DSMC but required)

``constant/dsmcProperties``
---------------------------

The top-level solver configuration, read by the ``dsmcCloud``
constructor (``dsmcCloud.C``), by ``buildConstProps()`` (species
database and collision pairs) and by the collision-rate and
binary-collision selectors.

.. list-table::
   :header-rows: 1
   :widths: 30 15 15 40

   * - Key
     - Type
     - Example
     - Role
   * - ``solution``
     - dict
     - see below
     - Solver activation and coupling controls (standard OpenFOAM).
   * - ``nEquivalentParticles``
     - scalar
     - ``625000``
     - Number of real molecules represented by each simulator
       particle. Lower values increase statistical resolution but
       raise the computational cost. A cell-level target of at
       least 10–20 particles is recommended.
   * - ``chemicalReactions``, ``chargedParticles``, ``adsorption``
     - Switch
     - ``false``
     - Not read by the current solver; kept in case files for
       compatibility. The chemistry is the ``reactions`` list of
       ``system/chemReactDict``, and surface processes are set on
       the wall patches.
   * - ``axisymmetricSimulation``
     - Switch
     - ``false``
     - Enables the axisymmetric geometry treatment (radial
       weighting); requires ``axisymmetricProperties``.
   * - ``axisymmetricProperties``
     - dict
     - see below
     - ``radialExtentOfDomain`` :math:`R` [m] and
       ``maxRadialWeightingFactor`` :math:`W`; the radial
       weighting factor at radius :math:`r` is
       :math:`1 + (W - 1)\,r/R`. Read only when
       ``axisymmetricSimulation`` is on.
   * - ``adaptiveSimulation``
     - Switch
     - ``false``
     - Enables adaptive time-stepping and cell weighting.
   * - ``cellWeightedSimulation``
     - Switch
     - ``false``
     - Enables cell-weighted parcel statistics.
   * - ``printReactionsToTerminal``
     - Switch
     - ``true``
     - Optional (default ``false``); prints per-reaction counts at
       each output.
   * - ``randomSeed``
     - label
     - ``12345``
     - Optional fixed seed of the random-number generator (offset
       per processor). By default the seed is the wall-clock time
       in whole seconds, so replicas launched in the same second
       are identical.
   * - ``BinaryCollisionModel``
     - word
     - ``LarsenBorgnakkeVariableHardSphere``
     - Binary collision model class. Alternatives:
       ``LarsenBorgnakkeVariableSoftSphere``,
       ``FHOVariableHardSphere``, ``VariableHardSphere``,
       ``VariableSoftSphere``, ``NoBinaryCollision``.
   * - ``collisionProperties``
     - dict
     - see below
     - Reference temperature (``Tref``, must be 273), the
       relaxation collision numbers, ``initialSubCellLevels`` and
       the optional :math:`Z_v(T)` keys. Required for every model.
   * - ``<Model>Coeffs``
     - dict
     - see below
     - Optional model-specific extras (the V-V block of the LB
       models, the FHO settings).
   * - ``collisionRateModel``
     - word
     - ``noTimeCounter``
     - Collision-pair selection algorithm (NTC is the standard
       choice).
   * - ``typeIdList``
     - wordList
     - see below
     - List of species present in the simulation; the *order* of
       this list defines the integer type-IDs used internally.
   * - ``rovibronicDatabase``
     - dict
     - see below
     - Species-database configuration. Required: without it the
       solver stops.
   * - ``moleculeProperties``
     - dict
     - see below
     - Optional per-species model switches.

Example excerpt, in the form used by the cases under
``run/0D/``:

.. code-block:: cpp

   nEquivalentParticles                        625000;
   adaptiveSimulation                          false;
   cellWeightedSimulation                      false;
   axisymmetricSimulation                      false;

   BinaryCollisionModel                        LarsenBorgnakkeVariableHardSphere;

   collisionProperties
   {
       Tref                                    273; // [K], fixed by the database
       rotationalRelaxationCollisionNumber     5;   // [-]
       rovibrationalRelaxationCollisionNumber  50;  // [-]
       rovibronicRelaxationCollisionNumber     500; // [-]
       initialSubCellLevels                    (1 1 1);
   }

   collisionRateModel                          noTimeCounter;

   typeIdList (O2 O O2+ O+ E- N2 N2+ NO NO+ N N+);

   rovibronicDatabase
   {
       computeEnergyLevels  true;
       databasePath         "constant/speciesCache";
   }

All masses and collision parameters come from the frozen species
database (:doc:`../classes/species_database_sources`);
``collisionProperties/Tref`` must equal the 273 K to which they are
referenced, and any other value stops the solver.

Relaxation collision numbers
````````````````````````````

The three collision numbers :math:`Z_r`, :math:`Z_{rv}`, and
:math:`Z_{rve}` govern the rotational, rovibrational, and
rovibronic relaxation rates respectively, and enter the
parallel-marginal cascade discussed in
:doc:`../theory/relaxation`. Representative orders of magnitude,
drawn from air chemistry at :math:`10^4~\mathrm{K}`, are:

* :math:`Z_r \sim 2\text{–}10` —  the rotational mode relaxes
  within a few collisions;
* :math:`Z_{rv} \sim 50\text{–}500` —  the vibrational mode is
  slower by one to two orders of magnitude;
* :math:`Z_{rve} \sim 500\text{–}5000` —  the electronic mode is
  the slowest and is only weakly populated below a few tens of
  thousands of Kelvin.

Setting any :math:`Z_k \to \infty` effectively freezes the
corresponding mode and is used as a diagnostic during the
phase-by-phase validation protocol (see
:doc:`../reference/validation`).

In addition to the three composite collision numbers,
``collisionProperties`` accepts an optional fourth, pure-vibrational collision number and a
set of keys that switch the constant vibrational collision number
for a temperature- and partner-dependent :math:`Z_v(T)`.

Vibrational-relaxation model
````````````````````````````

.. list-table::
   :header-rows: 1
   :widths: 32 14 18 36

   * - Key
     - Type
     - Example
     - Role
   * - ``vibrationalRelaxationCollisionNumber``
     - scalar
     - ``5``
     - Constant collision number for the pure-vibrational (V-T)
       window channel. Defaults to a very large value (channel
       off).
   * - ``vibrationalRelaxationModel``
     - word
     - ``valentini``
     - ``constant`` (legacy constant :math:`Z_v`),
       ``millikanWhite`` or ``valentini`` (temperature-dependent
       :math:`Z_v(T)`; ``valentini`` additionally consults the
       per-pair table). If absent, :math:`Z_v(T)` is auto-enabled
       when ``vibB1`` > 0.
   * - ``vibrationalRelaxationChannel``
     - word
     - ``pureVib``
     - ``rovib`` (default) routes :math:`Z_v(T)` to the
       rovibrational :math:`(v,J)` channel; ``pureVib`` routes it
       to the pure-vibrational :math:`v`-only channel.
   * - ``vibrationalSamplingMethod``
     - word
     - ``metropolisHastings``
     - Sampler for the joint multi-mode vibrational state of
       POLYATOMIC molecules (Pfeiffer et al., Phys. Fluids 28,
       027103 (2016), Sec. III).  ``acceptanceRejection``
       (default) keeps the joint acceptance-rejection kernel;
       ``metropolisHastings`` switches the nonreactive vib
       channel and the post-reaction product redistribution to
       the random-walk Metropolis chain (paper Eqs. 31-32),
       whose cost grows linearly with the number of modes —
       recommended for many-mode species such as CH\ :sub:`4`.
       Both samplers target the identical distribution (verified
       to detailed balance); diatomics are unaffected. See
       ``docs/Development/Verification/pfeiffer2016_relaxation_conformance.md``.
   * - ``metropolisWalkLength``
     - label
     - ``500``
     - Random-walk length :math:`N_M` of the Metropolis chain
       (default 500, the paper's recommendation; CO\ :sub:`2`
       needs :math:`\geq 500`, CH\ :sub:`4` is insensitive down
       to 100).
   * - ``vibB1``, ``vibB2``, ``vibTHT``
     - scalar
     - ``30700``, ``0``, ``50000``
     - Global generalised-Millikan-White constants
       :math:`(B_1, B_2)` and the Park high-temperature limiter
       temperature :math:`T_{\mathrm{HT}}` (default 30000 K). See
       :doc:`../theory/relaxation`.
   * - ``vibrationalRelaxationData``
     - dict
     - see below
     - Per-pair :math:`(B_1, B_2, T_{\mathrm{HT}})` overrides,
       nested by vibrating species then collision partner.

The per-pair table is keyed by the vibrating species and then by
the collision partner (both must be members of ``typeIdList``); a
per-relaxer ``default`` block sets all partners of a vibrator, and
explicit partner blocks override individual pairs:

.. code-block:: cpp

   collisionProperties
   {
       Tref                                    273;
       vibrationalRelaxationModel              valentini;  // partner-dependent
       vibrationalRelaxationChannel            pureVib;    // Z_v(T) -> v-only
       vibrationalRelaxationCollisionNumber    1e30;       // overridden by Z_v(T)
       vibTHT                                  50000;

       vibrationalRelaxationData
       {
           N2
           {
               N2 { B1 30700; B2 0; THT 50000; }   // N2-N2 slow
               O  { B1 6140;  B2 0; THT 50000; }   // N2-O  fast
               Ar { B1 30700; B2 0; THT 50000; }   // N2-Ar slow
           }
       }
   }

Diagnostics: per-channel transition counters
````````````````````````````````````````````

``countInternalTransitions`` (Switch, ``collisionProperties``,
default ``off``) enables cumulative per-species transition-event
counters for the four LB window channels — rotational
:math:`J \to J'`, pure-vibrational :math:`v \to v'`, rovibrational
:math:`v \to v'` (aggregated over the final :math:`J'`), and
rovibronic :math:`n \to n'` — incremented at every non-reaction LB
draw and printed to the log (tag ``itc``) together with per-species
state-population snapshots at every write time. Combined with the
reservoir normalisation

.. math::

   k_{s \to s'} = \frac{\Delta(\text{counts})}{\Delta t \;
   N_{s} \; n_{\mathrm{tot}}}

this measures state-to-state rate coefficients directly (see
``docs/Development/Verification/lb_state_to_state_rates.md``). Enable only in
non-reactive runs: reaction-class trial redistributions pass through
the same sampler and would pollute the tallies.

Per-species model switches (``moleculeProperties``)
````````````````````````````````````````````````````

The optional ``moleculeProperties`` sub-dictionary, keyed by species
name, accepts only model switches:

* ``allowSpinForbiddenTransitions`` (bool) —  flips the electronic
  spin-conservation gate per species: ``true`` connects the full
  electronic manifold, ``false`` restricts LB electronic relaxation
  (and equilibrium initialisation) to the initial state's
  spin-multiplicity class;
* ``vibrationalCoupling`` (word) —  ``separable`` or ``coupled``
  polyatomic vibration (:doc:`../theory/rovibronic_levels`).

.. code-block:: cpp

   moleculeProperties
   {
       O2 { allowSpinForbiddenTransitions false; }   // spin-blocked
   }

The species data are frozen. An entry that sets ``mass``,
``diameter``, ``omega``, ``alpha``, ``charge``,
``rotationalDegreesOfFreedom``, ``vibrationalModes``,
``maintainOddEvenParity``, ``internalEnergyList``,
``degeneracyList`` or ``dissociationEnergy`` stops the solver with
a ``FatalError`` (see :doc:`../classes/species_database_sources`).

``rovibronicDatabase`` sub-dictionary
`````````````````````````````````````

Required; a case without it stops at start-up.

* ``computeEnergyLevels`` (Switch, default ``true``) —  builds the
  :math:`(n, v, J)` energy and degeneracy tables at start-up from
  the compiled species database. With ``false`` the diatomic and
  atomic tables are read back from ``databasePath`` when a cache
  file exists.
* ``databasePath`` (fileName, optional) —  directory in which the
  tables are cached, conventionally ``"constant/speciesCache"``.

``constant/speciesCache/``
--------------------------

The species data are compiled into the solver, not read from the
case. When ``databasePath`` is set, the solver writes one
``<species>.dat`` file per diatomic or atomic species (level table,
degeneracies, dissociation and ionisation energies, spin
multiplicities) as a cache; polyatomic ladders are not cached. The
cache is not validated against the database: after a database
change, rename every cache that may be read (the solver with
``computeEnergyLevels false``, or a Python oracle) and regenerate
it with ``dsmcInitialise``. The origin of every constant is
documented in :doc:`../classes/species_database_sources`.

``system/dsmcInitialiseDict``
-----------------------------

Specifies the initial particle distribution. The main entries are:

* ``configurations`` (list) —  one entry per sub-domain to populate.
  Each entry contains:

  * ``type`` —  fill strategy (``dsmcMeshFill`` is the standard
    whole-domain option; velocities are drawn from a Maxwellian);
  * ``numberDensities`` —  per-species number density in
    :math:`\mathrm{m}^{-3}`;
  * ``translationalTemperature`` —  Maxwell-Boltzmann sampling
    temperature for the particle velocities;
  * ``internalTemperature`` —  Boltzmann sampling temperature
    used for the rovibronic state indices :math:`(n, v, J)`
    (a single internal temperature; separate rotational,
    vibrational or electronic temperatures are not read);
  * ``velocity`` —  bulk flow velocity (vector).

Example:

.. code-block:: cpp

   configurations
   (
       configuration
       {
           type                        dsmcMeshFill;
           numberDensities
           {
               O2      1e23;
           };
           translationalTemperature    20000;
           internalTemperature         20000;
           velocity                    (0 0 0);
       }
   );

``system/boundariesDict``
-------------------------

Three top-level lists are read:
``dsmcPatchBoundaries``, ``dsmcCyclicBoundaries``, and
``dsmcGeneralBoundaries``. Each entry pairs a patch name with a
``boundaryModel`` drawn from the classes listed below.

Available patch models
``````````````````````

The following patch classes are implemented in
``src/lagrangian/DSMC/boundaries/derived/patchBoundaries/``:

.. list-table::
   :header-rows: 1
   :widths: 40 60

   * - Class
     - Purpose
   * - ``dsmcDiffuseWallPatch``
     - Fully diffuse reflection at a specified wall temperature.
   * - ``dsmcSpecularWallPatch``
     - Perfectly specular reflection.
   * - ``dsmcMixedDiffuseSpecularWallPatch``
     - Weighted mixture of diffuse and specular reflection.
   * - ``dsmcMixedDiffuseSpecularWallRotPatch``
     - **Rovibronic-aware** variant: the internal state is
       re-sampled on diffuse reflection using the wall temperature.
   * - ``dsmcCLLWallPatch``
     - Cercignani-Lampis-Lord scattering model.
   * - ``dsmcAccommodationWallPatch``
     - Maxwell wall with a separate accommodation coefficient per
       energy mode (optionally per species).
   * - ``dsmcRadiativeEquilibriumWallPatch``
     - Per-face wall temperature from the radiative balance.
   * - ``dsmcOutgassingWallPatch``,
       ``dsmcPumpWallPatch``
     - Prescribed species emission; capture with a probability, a
       pumping speed or a target pressure.
   * - ``dsmcCatalyticWallPatch``,
       ``dsmcAblatingWallPatch``,
       ``dsmcCoverageWallPatch``
     - Reactive gas-surface-interaction walls (probability-mode
       catalysis and ablation; finite-rate coverage chemistry). See
       the gas-surface interaction section below.
   * - ``dsmcDeletionPatch``
     - Particle sink (outflow or selective deletion).
   * - ``dsmcFreeStreamInflowPatch``
     - Maxwellian free-stream inflow.
   * - ``dsmcChapmanEnskogFreeStreamInflowPatch``
     - Chapman-Enskog (first-order non-equilibrium) inflow.
   * - ``dsmcWangPressureInlet``,
       ``dsmcLiouFangPressureInlet``,
       ``dsmcMassFlowRateInlet``
     - Alternative pressure- and mass-flow-rate-driven inlets.

Cyclic and field-patch variants of several of the above are also
available; see the source tree for the complete list.

``system/chemReactDict``
------------------------

Every reaction is an entry of the ``reactions`` list; an empty
list runs the case without chemistry. Each entry names a
``reactionModel`` and carries a ``dsmcReactionProperties``
sub-dictionary:

.. code-block:: cpp

   reactions
   (
       oxygenDissociation
       {
           reactionModel   dissociationIonisationTypeISameSpecies;

           dsmcReactionProperties
           {
               reaction                      oxygenDissociation;
               reactants                     (O2 O2);
               productsOfDissociatedMolecule (O O);
               productsOfIonisedMolecule     (O2+ E-);
               allowSplitting                yes;
               writeRatesToTerminal          no;
           }
       }
   );

The dissociation, exchange and ionisation thresholds of the QK
classes are **computed automatically** from the database entries
(:math:`D_0 = E_{\mathrm{diss}}(n{=}0, v{=}0, J{=}0)` and the
ionisation potentials) and are not supplied by the user.

A detailed description of each reaction model is given in
:doc:`../theory/chemistry`.

HCAO local-mode reaction models
```````````````````````````````

The channel-specific reaction models of Lauterbach, Tuttas &
Pfeiffer (2026) are compiled, but they act only on local-mode
polyatomic species (database ``vibModeBasis localMode``), and the
frozen species database on the main branch carries no such species;
a reaction that names a normal-mode species stops with a
``FatalError``. Their keys are:

* ``polyDissociationQKHCAO`` — one dissociation channel per local
  stretching mode (paper Eqs. 19–22).  Keys: ``reactants (A M)``, a
  ``channels`` sub-dictionary with one named block per breaking bond
  carrying ``stretchMode`` (0-based mode index), ``productMolecule``,
  ``productAtom`` and ``formationEnergy`` (:math:`-D_{0,j}` [J]);
  optional ``rotationCouplingGamma`` (paper Eq. 36, default 0).
  Competing open channels are drawn weighted by their excess energy.
* ``polyExchangeQK`` — mode-coupled QK exchange (paper Eqs. 23–26).
  Keys: ``productsOfExchangeReaction (C D)``, ``activationEnergy``
  (the *energetic* barrier :math:`E_a` [J], not an Arrhenius fit),
  ``modeCouplingAlpha`` (per-mode :math:`\alpha_j` list, one entry
  broadcasts), optional ``stericFactor`` (:math:`\sigma`, default 1),
  ``formationEnergy`` (0 K reaction energy for the post-reaction
  ledger), optional ``rotationCouplingGamma`` (Eq. 37, default 0).

Gas-surface interaction dictionaries
------------------------------------

The models are described in :doc:`../theory/wall_models` and verified
in :doc:`../reference/gsi_verification/index`. The keywords below are
those read by the source; the class headers under
``src/lagrangian/DSMC/`` carry the same Usage blocks.

Wall temperature (every re-emitting wall)
`````````````````````````````````````````

Read from ``<boundaryModel>Properties`` by every wall that re-emits
at a wall temperature (diffuse, mixed, CLL, accommodation, pump,
outgassing, catalytic, ablating and coverage walls):

.. code-block:: cpp

   temperature            1000;   // uniform value, initial face value
   wallTemperatureModel   radiativeEquilibrium;  // uniform (default) |
                                                 // radiativeEquilibrium |
                                                 // coupled
   wallTemperatureProperties      // radiativeEquilibrium only
   {
       emissivity            0.85;   // (0, 1], required
       backgroundTemperature 0;      // radiative sink [K]
       relaxationFactor      0.2;    // (0, 1]
       updateInterval        10;     // steps per update
       minTemperature        50;
       maxTemperature        1e5;
       sampleStartTime       0;      // start of the Tw/q averaging ledger
   }

A non-uniform model on a wall that does not re-emit at a face
temperature (specular, deletion, the ``*Field*`` walls, the dedicated
radiative-equilibrium wall) is a ``FatalError``; ``coupled`` is set
by the conjugate solid of ``dsmcFoamAblation``.

Probability-mode reactive walls
```````````````````````````````

``dsmcCatalyticWallPatch`` and ``dsmcAblatingWallPatch`` take a
``reactions`` entry that is either an inline dictionary or a list of
names resolved against the ``surfaceReactions`` block of
``system/surfaceChemReactDict``:

.. code-block:: cpp

   // system/surfaceChemReactDict
   surfaceReactions
   {
       oxidiseO   { type srFiniteRate; reactant O;  product CO;
                    A 0.63; n 0.0; Ta 1160.0;
                    nCConsumed 1; nReactantConsumed 1; }
       boudouard  { type srFiniteRate; reactant CO2; product CO;
                    secondaryProduct CO; A 0.9; n 0.0; Ta 0.0;
                    nCConsumed 1; nReactantConsumed 1; }
       recombineO { type srRecombination; reactant O; product O2;
                    gamma 0.07; betaAcc 0.5; Erecomb 8.203e-19; }
   }
   surfaceMaterials
   {
       graphite { solidDensity 1800; carbonMass 1.9944734729e-26; }
   }

   // system/boundariesDict
   boundaryModel dsmcAblatingWallPatch;
   dsmcAblatingWallPatchProperties
   {
       temperature 2000;
       velocity    (0 0 0);
       material    graphite;      // or solidDensity and carbonMass
       reactions   ( oxidiseO boudouard recombineO );
   }

.. list-table::
   :header-rows: 1
   :widths: 25 75

   * - ``type``
     - Keywords
   * - ``srFiniteRate``
     - ``reactant``, ``product``, ``A`` (required), ``n``, ``Ta``
       (default 0), ``nCConsumed``, ``nReactantConsumed``, optional
       ``secondaryProduct``
   * - ``srRecombination``
     - ``reactant``, ``product``; one of ``gamma``,
       ``gamma0`` + ``Ea`` [J/mol], ``gammaA`` + ``Ta`` [K]
       (optional ``n``), or ``gammaTable ((T0 g0) (T1 g1) ...)``;
       ``Erecomb`` [J], ``betaAcc`` (default 1)
   * - ``srAbsorption``
     - ``reactant``, optional ``A`` (default 1), ``n``, ``Ta``
   * - ``srNeutralisation``
     - ``reactant``, ``product``, ``workFunction`` [eV], ``betaAcc``,
       optional ``releasedEnergy`` [eV], ``A``, ``n``, ``Ta``

Finite-rate mechanisms and the coverage wall
````````````````````````````````````````````

``dsmcCoverageWallPatch`` takes a native mechanism by name, a SPARTA
import, or the legacy keywords (translated at start):

.. code-block:: cpp

   boundaryModel   dsmcCoverageWallPatch;
   dsmcCoverageWallPatchProperties
   {
       temperature   1000;             // element temperature [K]
       velocity      (0 0 0);
       mechanism     sample;           // system/surfaceChemReactDict
       // or
       spartaMechanism
       {
           gsFile      "sample-GS_2.surf";   // in constant/
           psFile      "sample-PS_2.surf";   // optional
           siteDensity 6.022e18;             // SPARTA n_sites [m^-2]
           temperature 1000;                 // SPARTA twall [K]
           nsync       1;
           // psIntegrator timeCounter;      // default of the import
       }
       scatterModel  cll;              // default kernel (default diffuse)
       cllProperties { temperature 300; alphaN 0.5; alphaT 0.5;
                       alphaRot 0.5; alphaVib 0.5; }
       material      graphite;         // optional surfaceMaterials entry
       printInterval 100;              // optional
       elementTallies false;           // optional
       wallTemperatureModel uniform;   // optional
   }

The native mechanism, in ``system/surfaceChemReactDict``:

.. code-block:: cpp

   surfaceMechanisms
   {
       sample
       {
           siteSets      { s { siteDensity 6.022e18; } }
           adsorbates    { O(s)  { siteSet s; initialCoverage 0; }
                           CO(s) { siteSet s; bindingEnergy 2.3;
                                   bindingEnergyUnit eV; } }
           bulk          ( C(b) );
           normalisation sparta;        // sparta | sg25
           stoichiometry combinatorial; // combinatorial | power (mandatory)
           coverageUpdate immediate;    // immediate | sync
           // nsync              1;
           // psIntegrator       exponential;  // | timeCounter | stochastic
           // psSubStepTolerance 0.1;
           // psMaxSubSteps      100;
           temperature   element;       // element | fixed
           // fixedTemperature   1000;
           // probabilityCap     1;     // perParticle channels only
           // reactionHeat       computed;     // | none
           // material           graphite;
           // adsorption { O { S0 { A 0.85; b 0; Ea 0; } Kkis { A 0; }
           //                  alpha 1; siteSet s; } }   // sg25 only
           reactions
           {
               adsO { type AA; reaction "O(g) --> O(s)";
                      rate { A 1.0; b 0; Ea 0; } alpha 1; }
               lh1  { type LH1; reaction "O(g) + O(s) --> CO2(g)";
                      rate { A 536.3e5; b 0; Ea 655.65; } alpha 1;
                      products { CO2 { scatterModel td;
                                       tdProperties { temperature 300; } } } }
               dsO  { type DS; reaction "O(s) --> O(g)";
                      rate { A 0.050457; b 2; Ea 3177.17; } }
           }
       }
   }
   surfaceMaterials
   {
       graphite { solidDensity 1800; }   // optional formationReference
                                         // { X(b) h; } [kJ/mol], atomMass
   }

Reaction types: GS ``AA``, ``DA``, ``ER``, ``CI``, ``LH1``, ``LH3``,
``CD``, ``prob``; PS ``DS``, ``LH2``, ``LH4``, ``SB``. Optional keys
of a reaction: ``id``, ``rateStyle`` (``arrhenius`` | ``constant``),
``alpha``, ``siteSet``, ``kisliuk { form sparta|sg25|legacy; A; b; Ea; }``
(``form`` mandatory), ``rateForm`` (``efficiency`` | ``maxwellian`` |
``perParticle``), ``heatOfReaction`` with ``heatOfReactionUnit``
(``J`` | ``K`` | ``eV``), ``spectator``, and ``products`` (gas-product
kernels by name or as a list in token order).

Legacy coverage keywords (translated into a mechanism): ``siteDensity``
or ``material``; ``species { X { stick; stickEnergy; stickingModel
langmuir|kisliuk; kisliukK; dissociateTo; desorbPrefactor;
desorbEnergy; desorbLateral; desorbPrefactorCov; initCoverage; } }``;
``reactions { name { type ER|CID|LH; reactant; coReactant; product;
gamma; A; Ta; } }``; optional ``psIntegrator``.

Scattering kernels
``````````````````

``scatterModel`` selects the default kernel of a reacting wall and,
inside ``products``, the kernel of a reaction product; coefficients go
in ``<scatterModel>Properties``:

.. list-table::
   :header-rows: 1
   :widths: 18 82

   * - Kernel
     - Keywords (``temperature`` optional in every kernel, else the
       element temperature)
   * - ``diffuse``
     - ``accommodation`` (diffuse fraction, default 1)
   * - ``specular``
     - none
   * - ``cll``
     - ``alphaN``, ``alphaT``, ``alphaRot``, ``alphaVib``, optional
       ``partial`` (eccentricity in [0, 1))
   * - ``td``
     - optional ``barrier`` [K], ``bond (Bt Br Bv)`` [K],
       ``initenergy (ft fr fv)``
   * - ``impulsive``
     - ``model softsphere|tempvar``, ``energyRatio`` and
       ``effectiveMass`` (softsphere), ``u0a`` and ``u0b`` (tempvar),
       ``alpha``, ``thetaPeak``, ``cosThetaPower``, ``cosPhiPower``,
       optional ``step``, ``double``, ``intenergy (fr fv)``,
       ``ladderSearch bisection|linear``
   * - ``adiabatic``
     - none

The internal-state sampler of the gas-phase equilibrium draws is
selected in ``constant/dsmcProperties`` by
``internalStateSampler alias;`` (default) or ``rejection``.

Immersed surface
````````````````

``immersedAblationProperties`` in ``constant/dsmcProperties``:

.. code-block:: cpp

   immersedAblationProperties
   {
       // geometry: analytic shape or STL
       shape        cylinder;          // plane (point, normal) |
                                       // sphere | cylinder (centre,
                                       // radius; cylinder: axis)
       centre       (1.5e-3 0 5e-5); axis (0 0 1); radius 5e-4;
       // stlFile   "constant/triSurface/body.stl";
       surfaceType  implicit;          // implicit | explicit
       cutCellVolumes    true;         // default
       recessionInterval 1;            // default
       temperature  2000;
       area         3.14159e-7;
       material     graphite;          // or solidDensity, carbonMass

       // probability mode: single reaction ...
       reactant O;  product CO;  A 0.63;  n 0;  Ta 1160;   // or gamma
       // ... or a reactions list (srFiniteRate, srRecombination, ...)
       // reactions { oxO { type srFiniteRate; reactant O; product CO;
       //                   A 0.63; Ta 1160; nCConsumed 1; } }
       // mechanism mode
       // mechanism  b5rec;            // or spartaMechanism { ... }
       // scatterModel diffuse; printInterval 100; ledgerCheck true;
       // elementTallies false;
       // wallTemperatureModel radiativeEquilibrium;   // per cut cell
       // wallTemperatureProperties { emissivity 0.85; ... }

       // optional
       // radiativeEquilibrium true; emissivity 0.85;  // global Tw
       // sublimation true; sublimationAlpha 1;
       // sublimationProducts { C3 { pvapA ...; pvapB ...; nCarbon 3; } }
       // perCellRecession true;      // former cell-centred level set
       // patoCoupling true; patoCouplingInterval 100;
   }

A mechanism needs the cut cells of the implicit or explicit surface;
the analytic and level-set paths keep the probability mode.

``dsmcFoamAblation``: receding walls and the conjugate solid
````````````````````````````````````````````````````````````

Body-fitted recession of an ablating or coverage wall, in
``constant/dynamicMeshDict`` (the ``pointDisplacement`` condition of
the patch must be ``fixedValue``):

.. code-block:: cpp

   ablationRecession { patch wall; accelerationFactor 1; }

The conjugate solid, in ``constant/conjugateProperties`` (it recedes
the wall itself, so it excludes ``ablationRecession``):

.. code-block:: cpp

   solidRegions          (solid);
   couplings
   {
       plate { gasPatch plate; solidRegion solid; solidPatch top; }
   }
   couplingInterval      1000;   // DSMC steps per window
   solidStepsPerWindow   10;
   solidDeltaT           1e-4;   // physical solid time step [s]
   emissivity            0.85;
   backgroundTemperature 0;
   nOuterCorrectors      3;
   prescribedHeatFlux    1e7;    // optional (verification)
   maxRecession          2e-4;   // optional: write and stop [m]
   meltFilm                      // optional
   {
       bodyForce         (0 0 0);
       freeFlight        no;
       separation        full;   // full | partial | none
       weberCritical     12;
       maxCourant        0.4;
       sampleInterval    5;
       dropletEmissivity 0.1;
       // prescribedShear, initialFilm { }, testDroplet { } (verification)
   }

Each solid region has ``constant/<region>/polyMesh``,
``dynamicMeshDict`` (a motion solver, to recede) and
``solidProperties`` (``rho``, ``cp``, ``k``, ``Tmelt``, ``Lmelt``,
``T0``; ``cp`` and ``k`` may be any ``Function1`` of :math:`T`;
optional ``cellZones`` overrides; for the film ``rhoLiquid``,
``muLiquid``, ``sigmaLiquid``, ``cpLiquid`` and optionally ``Tboil``,
``Lvap``, ``molarMass``), ``system/<region>/fvSchemes`` and
``fvSolution``, ``0/<region>/T`` (``mixed`` on the coupled patches) and
``0/<region>/pointDisplacement`` (``fixedValue`` on the coupled
patches). ``constant/regionProperties`` (``regions ( gas (region0)
solid (solid) );``) is read by ``decomposePar -allRegions`` and
``reconstructPar -allRegions``. The couplings must be disjoint: no
patch in two couplings and no point shared by two coupled patches of
one mesh. The former ``solidCase`` layout is refused.

``system/controlDict``
----------------------

Standard OpenFOAM; the rovibronic extension adds a single
convenience key:

* ``nTerminalOutputs`` (label) —  number of solver time-steps
  between terminal progress messages.

The ``application`` entry is informational only; the executable
that must actually be invoked is ``dsmcFoam`` (or
``dsmcFoamAblation`` for the moving-mesh and conjugate ablation
cases), regardless
of the string supplied here.
