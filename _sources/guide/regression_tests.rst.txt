Regression tests
================

The solver ships a **manufactured golden-value regression suite**
under ``run/regression/``. It exercises the currently installed
library against a fixed set of analytic or literature reference
values, and returns a single PASS/FAIL verdict suitable for use as
a merge gate. The suite is deliberately fast (short 0-D and small
GSI cases) so that it can be run after every recompile.

What it covers
--------------

The suite comprises **23 checks** in five groups:

.. list-table::
   :header-rows: 1
   :widths: 14 10 76

   * - Group
     - Count
     - Coverage
   * - ``A.relax``
     - 8
     - Adiabatic thermal relaxation of each polyatomic
       (CO\ :sub:`2`, CH\ :sub:`4`, H\ :sub:`2`\ O, CH\ :sub:`3`,
       NH\ :sub:`3`, O\ :sub:`3`, N\ :sub:`2`\ O, HCN) to a single
       energy-conserving equilibrium temperature.
   * - ``B.detbal``
     - 4
     - Detailed balance: starting from
       :math:`T_{\mathrm{trans}} = T_{\mathrm{int}}`, confirm no
       spurious drift (CO\ :sub:`2`, CH\ :sub:`4`, H\ :sub:`2`\ O,
       CH\ :sub:`3`).
   * - ``C.chem``
     - 5
     - Chemistry rates and atom conservation: CO\ :sub:`2`
       dissociation, CO\ :sub:`2` + O exchange, CH\ :sub:`4` →
       CH\ :sub:`3`, Saturn H\ :sub:`2` dissociation, and the
       CH\ :sub:`4` pyrolysis chain (C / H nuclei conservation).
   * - ``D.gsi``
     - 5
     - Gas-surface interaction: Park oxidation efficiency,
       :math:`\gamma(T)` catalysis, Kisliuk sticking, Mars
       ablation mass loss, recombination-energy balance.
   * - ``E.smoke``
     - 1
     - End-to-end smoke test (Earth ablation reaches ``End`` with
       no crash).

The acceptance criteria are documented per group in
``run/regression/README.md``: relaxation requires
:math:`|T_{\mathrm{trans}} - T_{\mathrm{int}}|/T_{\mathrm{eq}} <
2.5\%` and :math:`|T_{\mathrm{eq}} - \text{golden}|/\text{golden}
< 3\%`; detailed balance requires drift :math:`< 1.5\%`; chemistry
rates must lie inside a documented ratio window around the
reference Arrhenius rate; atom conservation requires nuclei drift
:math:`< 0.1\%`; GSI checks compare against the analytic surface
law.

How it works
------------

The entry point ``run_regression.sh`` sources the
``of-rovibronic`` environment if ``dsmcFoam`` is not already on the
path, then hands off to ``driver.py``. The driver, for each case,
clones the source case (from ``run/0D`` or ``run/GSI``) into a
git-ignored ``work/`` directory, optionally rewrites the bath
temperature, end time and particle weight, runs the
``blockMesh`` → ``dsmcInitialise`` → ``dsmcFoam`` pipeline, and
applies the case's golden-value check. The suite **rebuilds
nothing** —  it exercises the library currently installed by
``wmake``.

The golden values live in the ``CASES`` manifest in ``driver.py``;
for example the Saturn check pins the Higdon dissociation rate
prefactor :math:`A = 1.727\times10^{-11}` with exponent
:math:`\eta = -1.0` and :math:`T_a = 51958~\mathrm{K}`, and the
Park oxidation check pins the efficiency
:math:`0.63\,e^{-1160/2000} = 0.3527`.

Running it
----------

.. code-block:: bash

   source ~/WORKSPACE/OpenFOAM/OpenFOAM-v2512/etc/bashrc-rovibronic
   cd src/lagrangian/DSMC && wmake -j20          # build the library first
   cd ../../../run/regression
   ./run_regression.sh                            # whole suite
   ./run_regression.sh relax_CO2 chem_Saturn_H2   # named case(s) only

The driver prints a ``PASS / FAIL CASE GROUP MEASURED GOLDEN TOL
DETAIL`` table to standard output and mirrors it to
``last_run.log``, ending with an ``N / 23 PASS`` summary. The
process exits ``0`` only when every check passes, so the script can
be wired directly into a continuous-integration gate. Concurrency
is tunable through the ``REG_WORKERS`` environment variable
(default 12, kept at or below the workstation core budget).

Interpreting a failure
----------------------

A run that never reaches ``End`` is reported as a ``RUNFAIL`` and
points to a broken case clone. A genuine ``FAIL`` against a golden
value that reflects a deliberate physics change in the library is a
**real regression**: the correct response is to investigate the
code, not to widen the tolerance. Only a tolerance that is too
tight for the case set-up itself (statistical noise, equilibration
time) should be adjusted, and then in the manifest with a comment.
