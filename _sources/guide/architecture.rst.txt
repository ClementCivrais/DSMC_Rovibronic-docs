Source-tree architecture
========================

The present page maps out the solver's source layout and the
principal classes that a developer is likely to encounter when
extending the rovibronic machinery. Every subsystem is documented
class by class in the companion :doc:`../classes/index` section;
the present page is the quickest way to locate a given piece of
functionality in the tree.
How the executables and their regions exchange data during a run is
shown in :doc:`solvers/index`.

Top-level layout
----------------

.. code-block:: text

   src/                 C++ libraries (DSMC core + rovibronic extension)
   applications/        Solvers (dsmcFoam, dsmcFoamAblation) and dsmcInitialise
   tutorials/           Tutorial cases
   run/                 Verification and research cases (0D, 3D, GSI, …)
   docs/                User guides (PDF), Sphinx source for the docs site,
                        development records
   tools/               Maintenance scripts
   Allwmake             Top-level build driver
   BUILD.md             Build instructions

Applications
------------

* ``applications/solvers/discreteMethods/dsmcFoam/`` —  the solver
  executable. The ``Make/files`` line ``EXE =
  $(FOAM_USER_APPBIN)/dsmcFoam`` fixes the binary name to
  ``dsmcFoam``.
* ``applications/solvers/discreteMethods/dsmcFoamAblation/`` —
  the same solver on a dynamic mesh, for receding ablating walls
  and the optional conjugate solid; it is built separately from
  ``Allwmake``.
* ``applications/utilities/preProcessing/DSMC/dsmcInitialise/``
  —  the pre-processing utility that writes the ``0/`` time
  directory from ``system/dsmcInitialiseDict``.

Build driver
------------

The top-level ``Allwmake`` script, invoked from the repository
root, carries out three jobs:

#. creates symbolic links from the repository's
   ``src/lagrangian``, ``applications/solvers`` and
   ``applications/utilities`` directories into
   ``$WM_PROJECT_USER_DIR`` on the first compilation;
#. builds ``liblagrangianCloudBase`` and ``libDSMC_MNF`` under
   ``$WM_PROJECT_USER_DIR/src/lagrangian/``;
#. builds ``dsmcFoam`` and ``dsmcInitialise``.

``dsmcFoamAblation`` is built afterwards with ``wmake`` in its own
directory (``BUILD.md``). Build products are not tracked by git.

The use of symbolic links allows the OpenFOAM build machinery to
pick the sources up as user-side additions and leaves the primary
repository tree read-only from the build's standpoint.

Random-number generator
-----------------------

A single ``Foam::Random`` instance, ``rndGen_``, is held on the
cloud (``dsmcCloud.H``, member variable). It is constructed in the
``dsmcCloud`` constructor with the seed

.. code-block:: cpp

   rndGen_(label(clock::getTime()) + 7183*Pstream::myProcNo())

i.e. the wall-clock time in whole seconds offset by a per-rank
multiple of 7183. When ``constant/dsmcProperties`` sets
``randomSeed N;``, the generator is reset to ``N`` plus the same
per-rank offset. All downstream RNG consumers access this single
instance through ``cloud_.rndGen()``.

This **single entry point makes deterministic regression testing
feasible**: a fixed ``randomSeed`` seeds every downstream RNG
consumer automatically. Without it, replicas launched in the same
second are bit-identical. The design of the planned regression-test
infrastructure is documented in :doc:`regression_tests`.
