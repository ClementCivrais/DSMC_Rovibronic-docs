Running a Case
==============

Reference cases are distributed under ``tutorials/`` and, as
focused verification cases, under ``run/0D/``. We describe below the standard invocation
sequence, together with the parallel variant; a detailed walk-through
of dictionaries, mesh requirements, and species-database wiring is
given in the companion setup guide at
``docs/UserGuide/SetupGuide/dsmc_case_setup_guide.pdf``, while each input
dictionary is documented individually in :doc:`input_reference`.

Serial execution
----------------

.. code-block:: bash

   cd run/0D/<case>
   blockMesh
   dsmcInitialise
   dsmcFoam

The three stages carry out, respectively, mesh generation, particle
initialisation (drawing positions, velocities, and rovibronic states
from the distributions specified in ``system/dsmcInitialiseDict``),
and the time integration itself. Post-processing may then be carried
out with the standard OpenFOAM tools (``paraFoam``, ``postProcess``)
or with the solver-specific utilities under
``applications/utilities/`` —  see :doc:`post_processing` for an
overview.

Parallel execution
------------------

For production runs on multiple cores we decompose the domain,
launch the solver in parallel, and reconstruct the resulting
fields:

.. code-block:: bash

   decomposePar
   mpirun -np <N> dsmcFoam -parallel
   reconstructPar

As the DSMC load balance is particle-count driven, strongly
non-uniform flows benefit from a finer spatial decomposition, or
from on-the-fly load balancing where available.

Startup diagnostics
-------------------

At initialisation the solver prints the collision-pair table
taken from the frozen species database
(``Collision pairs (d_ref [m], omega, alpha; Tref = 273 K)``), the
level count of every species, and, for each dissociation channel,
the asymptote-matching table. With the generated spectroscopy the
matching errors are at round-off; a larger value is symptomatic of
an inconsistent species entry. A case that sets species data in
``moleculeProperties``, lacks the ``rovibronicDatabase``
sub-dictionary, or uses a ``collisionProperties/Tref`` other than
273 stops here with a ``FatalError`` (see
:doc:`../classes/species_database_sources`).

It is useful to keep the first few lines of a clean run's standard
output as a baseline; the startup section is deterministic and any
change in the printed collision pairs, level counts or heats of
reaction is a reliable signal that the species database has changed
between runs. For reproducible runs, or for independent replicas
launched together, set ``randomSeed`` in
``constant/dsmcProperties``: the default seed is the wall-clock time
in whole seconds.
